# SentinelGrid V01 — 지정구역 무인 순찰·상황인지 플랫폼

SentinelGrid는 도시 공공구역, 공장 부지, 산업시설 외곽처럼 경계가 정의된 지역을 가상 무인 순찰체가 반복 순찰하고, 관제 시스템이 임무 진행·관측 신뢰도·통신 장애·안전 사건을 관리하는 플랫폼이다.

SentinelGrid는 빈 저장소에서 시작하는 **Greenfield 프로젝트**다. 기존 시스템의 코드, 데이터베이스, API 호환성이나 전환 절차를 전제로 하지 않는다. 민간 도시 운영과 산업현장의 안전 순찰이라는 목적에 맞춰 도메인, UI, 계약과 서비스를 처음부터 설계하며 문서 버전도 `V01`부터 시작한다.

개발은 도메인과 사용자 기능 단위의 수직 슬라이스로 진행한다. 각 기능에서 React+TypeScript 화면과 상태를 먼저 확인한 뒤 필요한 도메인 규칙과 계약을 정의하고, Go·Rust·Python 구현과 실제 연동까지 완료한다. 프론트엔드와 백엔드를 별도 단계로 쌓지 않고 짧게 번갈아 개발한다.

## 프로젝트 정체성

- 프로젝트명: **SentinelGrid**
- 한글 정의: **지정구역 무인 순찰·상황인지 플랫폼**
- 핵심 대상: 도시 공공구역, 공장·물류 부지, 산업시설 외곽
- 초기 순찰체: 가상 UAV
- 확장 대상: 지상 순찰 로봇, 고정 센서, 현장 카메라
- 핵심 가치: 순찰 자동화보다 **관측 신뢰성, 임무 지속성, 사건 추적성**

## 기술 구조

- Go: 순찰 임무, 경로, 통제권, 명령, 사건, 감사 원장의 System of Record
- Rust: 텔레메트리 수집, 장치 세션, 통신 검증, 우선순위와 backpressure
- Python: 시뮬레이션, 이상 후보 탐지, 경량 ML, 자체 LLM·RAG, MLOps
- React+TypeScript: 지도 기반 관제, 임무·사건·명령 상태 시각화
- PostgreSQL/PostGIS, Redis Streams, Object Storage: 공간 원장, 이벤트 전달, 재현 데이터

## 설계 원칙

1. 순찰체 상태와 데이터 품질을 분리한다.
2. 관측이 부족하면 정상·위험을 단정하지 않고 `UNKNOWN`을 표시한다.
3. AI는 설명·검색·이상 후보 탐지를 지원하며 명령 권한을 갖지 않는다.
4. 원본 영상보다 사건 메타데이터와 필요한 증거 참조를 우선한다.
5. 얼굴 인식, 개인 식별·지속 추적, 자동 제재, 공격·무장 기능은 구현하지 않는다.
6. 도시와 공장 운용 정책은 하나의 규칙으로 합치지 않고 Site Profile로 분리한다.

## V01 완료 정의

가상 순찰체가 도시 또는 공장 Site Profile의 경로를 수행하고, 통신 단절·중복·역순 이벤트가 발생해도 최신 상태와 신선도를 일관되게 복원해야 한다. 운영자는 미순찰 구간, 결과 미확인 명령, 이상 사건의 근거를 한 화면에서 확인할 수 있어야 한다.
