# 데이터베이스·이벤트 아키텍처

## 1. 저장소의 역할

| 저장소 | 용도 | 저장하지 않는 것 |
|---|---|---|
| PostgreSQL | 임무, 명령, 권한, 사건, 감사 이력 | 고빈도 원본 전체 |
| PostGIS | 순찰구역, 경로, 금지구역, 위치 질의 | 렌더링 전용 형상 |
| Redis Streams | 텔레메트리·이벤트 전달, 소비자 그룹 | 장기 보존 원장 |
| Object Storage | 재현 데이터셋, 보고서, 모델 산출물 | 온라인 트랜잭션 상태 |

원본 이벤트와 최신 상태 projection을 분리한다. 최신 상태는 다시 만들 수 있어야 하며, 임무·명령·승인·통제권 기록은 Go 서비스의 트랜잭션 원장으로 관리한다.

## 2. 핵심 데이터 모델

- `patrol_area`, `route`, `checkpoint`, `mission`, `mission_assignment`
- `vehicle`, `device_session`, `control_lease`
- `command`, `command_attempt`, `command_observation`
- `telemetry_event`, `vehicle_snapshot`, `data_freshness`
- `incident`, `evidence_reference`, `alert_group`
- `policy_version`, `model_version`, `audit_event`

모든 이벤트는 `event_id`, `vehicle_id`, `session_id`, `sequence`, `occurred_at`, `received_at`, `schema_version`을 가진다. 좌표계, 단위, 시간 기준은 계약에 고정한다.

## 3. 정합성 패턴

Go 트랜잭션에서 상태 변경과 outbox 기록을 함께 커밋한다. 발행기는 outbox를 Redis Streams로 전달하고, 소비자는 `event_id` 기반으로 멱등 처리한다. DB와 이벤트 브로커를 동시에 쓰는 dual-write는 금지한다.

역순·중복·지연 이벤트는 삭제하지 않고 수신 사실을 남긴다. 최신 projection 반영 여부는 세션과 sequence 규칙으로 결정한다. 신선도 기준을 넘은 값은 `STALE`, 필요한 관측이 없으면 판단 결과는 `UNKNOWN`이다.

## 4. 공간 데이터 정책

- 모든 API 좌표는 WGS84를 기본 계약으로 사용한다.
- 거리·면적 계산은 적절한 투영 좌표계로 변환한다.
- 구역 변경은 버전으로 관리하며 진행 중 임무가 참조한 버전을 보존한다.
- 원본 영상 대신 사건 시각·구역·센서·증거 참조를 기본 저장한다.

## 5. 복구 검증

백업 복원 뒤 mission/command/audit 불변조건과 event replay 결과를 대조한다. 목표는 RPO/RTO 숫자 선언보다 먼저 실제 복원 시간과 누락 범위를 반복 측정하는 것이다.
