# 도메인 모델과 요구사항

## 1. Bounded Context

| Context | 책임 | 주요 Aggregate |
|---|---|---|
| Area Registry | 순찰·제한 구역과 체크포인트 | PatrolArea, Route |
| Patrol Mission | 임무 계획, 배정, coverage | Mission, Assignment |
| Command & Control | 통제권, 명령, 승인, 결과 | ControlLease, Command |
| Operational Picture | 기체 최신 상태와 신선도 | VehicleSnapshot |
| Incident Management | 이상 후보, 확인, 조치, 종결 | Incident, Evidence |
| Identity & Audit | 사용자·장비 신원과 감사 | Principal, AuditEvent |

## 2. 상태 모델

임무는 `DRAFT → READY → ACTIVE → COMPLETED/ABORTED`로 전이한다. 명령은 `REQUESTED → AUTHORIZED → DISPATCHED → ACCEPTED → EXECUTING → SUCCEEDED/FAILED/EXPIRED/UNKNOWN`으로 관리한다. ACK와 목표 상태 도달은 별도 증거다.

기체 상태와 데이터 품질을 섞지 않는다. `battery=70%`와 `battery freshness=STALE`을 함께 보존하고, 임무 가능성은 경로·복귀 거리·센서·링크 조건을 이용한 별도 판단으로 만든다.

## 3. 핵심 불변조건

1. 한 기체에는 동시에 하나의 유효한 통제 lease만 존재한다.
2. 만료되거나 이전 세션의 명령은 실행할 수 없다.
3. 임무 명령은 유효한 임무·기체·정책 버전에 연결된다.
4. 동일 idempotency key의 효과는 한 번만 발생한다.
5. 근거가 부족하면 정상 또는 위험을 단정하지 않고 `UNKNOWN`을 반환한다.
6. coverage는 실제 관측과 품질 조건을 충족한 구간만 인정한다.

## 4. 대표 요구사항

| ID | 요구사항 | 검증 증거 |
|---|---|---|
| PAT-01 | 운영자는 지도에서 순찰구역과 체크포인트를 정의한다. | 공간 계약·API 시험 |
| PAT-02 | 시스템은 순찰 완료·누락 구간을 구분한다. | replay 결과 |
| TEL-01 | 센서별 신선도와 마지막 관측 시각을 표시한다. | 지연·누락 시험 |
| CMD-01 | 권한·lease·만료·멱등성을 재검증한다. | 경합·재전송 시험 |
| COM-01 | 링크 단절 시 사전 정의 정책을 적용하고 재접속 시 재동기화한다. | 단절 시나리오 |
| INC-01 | 사건 후보의 근거, 확인, 조치, 종결 이력을 남긴다. | 감사 추적 |
| AI-01 | AI 설명은 사실·추정과 근거 이벤트를 구분한다. | RAG 평가셋 |
| SEC-01 | 조회·승인·통제 권한을 분리한다. | 권한 행렬 시험 |
