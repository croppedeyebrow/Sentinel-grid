# AI·MLOps·RAG 아키텍처

## 1. AI의 역할

AI는 순찰 결과를 설명하고 이상 후보를 제시하지만, 기체 제어와 사건 확정 권한을 갖지 않는다.

1. 텔레메트리 기반 이상 후보 탐지
2. 순찰 누락·배터리 소모·통신 품질 분석
3. 경보와 운용 이력의 근거 기반 요약
4. SOP·시설 문서·과거 사건 검색과 보고서 초안 생성

## 2. 실행 구조

Python 분석 서비스는 Redis 또는 읽기 전용 데이터 뷰를 소비한다. 결과는 `analysis_result`로 반환하며 입력 범위, 특징 버전, 모델 버전, 점수, 불확실성, 근거 이벤트를 포함한다. Go는 정책에 따라 결과를 incident 후보로 반영한다.

LLM은 자체 호스팅 가능한 공개 가중치 모델을 추론 서버로 운영하고, 임베딩·재순위화·생성 단계를 분리한다. 모델 장애 시 검색 결과와 규칙 기반 요약으로 축소 운영한다.

## 3. MLOps 흐름

```mermaid
flowchart LR
    A["Replay 데이터"] --> B["검증·특징 생성"]
    B --> C["학습·평가"]
    C --> D["Model Registry"]
    D --> E["Shadow 추론"]
    E --> F["승인·배포"]
    F --> G["Drift·품질 감시"]
```

데이터셋, 라벨 기준, 전처리, 코드 커밋, 모델, 임계값, 배포 결과를 한 실행 ID로 연결한다. 시간·기체·비행 단위 분할로 데이터 누수를 막는다.

## 4. 평가 지표

- 이상 탐지: 미탐, 오경보, 탐지 지연, 기체별 편차
- RAG: 근거 재현율, 인용 정확도, 근거 없는 주장 비율
- 운용: 추론 지연, 메모리, fallback 비율, 판단 보류 비율

관측값이 오래됐거나 학습 범위를 벗어나면 확신을 낮추는 대신 `판단 보류`를 반환한다.

## 5. 보안·통제

- 분석 서비스에 기체 명령 자격증명을 발급하지 않는다.
- 민감 구역 문서는 접근 등급과 임무 범위로 필터링한다.
- 프롬프트와 검색 근거, 모델·정책 버전을 감사 가능하게 기록한다.
- 얼굴 식별, 개인 추적, 자동 제재·강제 조치는 범위에서 제외한다.
