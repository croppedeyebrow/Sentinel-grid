# 트레이드오프와 성공 기준

## 1. 구조 선택의 이점과 비용

| 선택 | 이점 | 비용·대응 |
|---|---|---|
| Go 임무 API | 단순한 배포, 높은 동시성, 명확한 SoR | DDD 표현력이 팀 규율에 의존 → 모듈 경계·ADR |
| Rust 수집 | 메모리 안전성과 예측 가능한 지연 | 학습·디버깅 비용 → 프로토콜 범위 제한 |
| Python 분석 | ML 생태계와 실험 속도 | 런타임·타입 경계 → 계약 검증·격리 |
| React/TS | 관제 UI 생산성과 타입 계약 | 실시간 상태 복잡성 → 서버 상태·UI 상태 분리 |
| Redis Streams | 가벼운 replay와 consumer group | 장기 원장·복잡 라우팅 한계 → DB/Object Storage 병행 |
| 서비스 분리 | 장애·확장 경계 명확 | 운영 복잡성 → 초기에는 소수 배포 단위 유지 |

## 2. 성공 기준

- 같은 replay를 반복했을 때 mission, command, coverage projection이 동일하다.
- 중복·역순·지연 텔레메트리에도 최신 상태 불변조건이 유지된다.
- ACK 손실과 재접속 뒤 명령 결과를 `확인·실패·미확인`으로 구분한다.
- 단일 기체 이탈 시 누락 구간과 대체 가능 기체를 표시한다.
- AI 결과에 모델·특징·근거 이벤트가 연결되고 근거 부족 시 보류한다.
- 도시·공장 시나리오에서 최소 권한, 데이터 최소 수집, 감사 추적을 검증한다.
- 배포 rollback과 DB 복원 실험을 문서화한다.

## 3. 단계별 범위 통제

MVP는 가상 기체, 사전 정의 구역, 단일 관제소, 운영자 승인 기반 명령에 집중한다. 실기체 연동, 영상 원본 분석, 자동 재배정, 복수 관제소 연합은 후속 단계다. 범위를 넓힐 때도 AI가 지휘 권한을 갖지 않는 원칙은 유지한다.
